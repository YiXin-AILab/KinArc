# 多模态配置

## 优化策略

确保媒体能到达合适的模型或工具，并在后续步骤保持可用引用。
区分内容理解、传输、归档与资产访问；配置不能创造模型或工具不具备的媒体能力。

### 1. 定位媒体链路

| 发现问题类型 | 建议操作内容 |
| --- | --- |
| 模型看不到附件 | 核对输入类型、模型能力与实际请求，再检查 URL 可达性或转换失败 |
| 初次可读，后续工具无法定位 | 检查归档规则是否命中，以及 Asset 句柄是否进入模型上下文 |
| 句柄存在但工具读取失败 | 检查工具的查找、授权与消费逻辑，不能只开启句柄提示 |
| 压缩后引用丢失 | 联动 [压缩](compaction.md) 检查摘要中的句柄与媒体信息 |
| 媒体可用但识别或业务判断错误 | 转查模型、[Tool](tools.md) 或任务规则，不反复切换传输配置 |

### 2. 按消费需求选择配置

明确谁在何时消费哪类媒体，是否需要跨步骤复用，再决定传输与归档。

- **选择传输方式**：URL 对目标服务可读时使用合适的 URL 路径；
  仅在可达性或接口契约需要时评估 base64，并核对下载延迟、请求体与类型支持。
- **选择归档范围**：按实际需要匹配 block_types 与 source_types；
  需要稳定引用时验证归档到 AssetStore，不为局部失败直接全量归档。
- **提供资产引用**：后续操作需要 asset_id 时启用句柄提示，并确认目标工具实际接受和读取该引用。
  句柄负责定位，不能代替媒体内容，也不能证明访问已授权。

例如，模型可以直接读取图片 URL，但后续处理工具只接受 asset_id 时，
需要打通归档、句柄提示和工具消费三步，仅改变模型传输方式不能解决。

### 3. 验证端到端消费

从输入到实际请求、资产引用与后续工具调用逐步核对，
覆盖目标来源、规则不命中和已归档内容；同时检查其他原有媒体路径。
在现有 Changelog 中记录失败环节、配置变化与实际消费结果，
并报告相关延迟或存储变化；归档成功不等于模型已理解内容。

## 优化质量控制

| 风险信号 | 修正动作与完成条件 |
| --- | --- |
| 所有失败都通过全量归档或 base64 处理 | 按来源与消费者缩小范围，验证目标问题已解决且开销合理 |
| 媒体、编码文本或副本反复进入上下文 | 检查请求与结果组织，移除无用重复，保留实际消费所需内容与引用 |
| 打开句柄提示后直接宣称历史引用已恢复 | 检查当前会话是否仍保留资产信息，使用明确输入验证；配置不自动修复已丢失历史 |
| 资产可见却仍不能处理 | 验证实际工具能力和授权，不能把引用展示当作处理能力 |
| 为提高成功率放宽下载或访问边界 | 保留宿主安全策略，定位来源、权限或兼容问题；本轮配置不能替代宿主能力 |

## 系统修改说明

media 定义输入媒体的归档条件、模型传输方式和 Asset 句柄可见性。存储后端及下载安全策略由 Runtime 管理。

| `media` 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `llm_transport` | auto | `auto` 尽量保留可读取 URL；`base64` 在 adapter 边界转换 |
| `include_asset_id_in_context` | false | 严格布尔值；在模型发送副本中加入 Asset 句柄提示 |
| `archive_rules` | `[]` | 不匹配则不因该规则主动归档 |
| `archive_rules[].block_types` | 必填 | image/audio/video/document 的非空、不重复组合 |
| `archive_rules[].source_types` | 必填 | url/base64 的非空、不重复组合 |

匹配输入在进入 Inbox 前归档到 AssetStore；已是 AssetSource 的内容不再次归档。

### 规则与请求语义

一条规则同时匹配 block_types 和 source_types；多条 archive_rules 任意命中即可归档。
空规则列表不关闭多模态输入或 Runtime 媒体安全限制。
include_asset_id_in_context 使用 YAML 布尔值 true / false。

传输方式不改变模型的媒体能力。base64 可能增加下载耗时和请求体大小，失败由 adapter 处理。

include_asset_id_in_context=true 在模型发送副本中、相应 Asset 媒体前加入
<asset_reference>；不向 MessageManager 原始内容或公开消息新增该提示文本。
摘要模型会被要求一起保留句柄与媒体摘要，Runtime 不解析或校验摘要 XML。
关闭时已压缩且丢失的句柄，后续再打开不会自动恢复。

### 完整媒体示例

合并到现有 AgentConfig：

```yaml
media:
  llm_transport: auto
  include_asset_id_in_context: true
  archive_rules:
    - block_types: [image, audio, video, document]
      source_types: [url, base64]
```

此规则覆盖全部媒体类型和输入来源。

### 修改范围

需要媒体业务处理时优化目标应用的 Tool，并保持资产引用和授权契约。
存储后端、鉴权、下载安全策略和 Runtime 限额不属于本轮应用配置调优范围。

### 验证要求

覆盖每种 block/source、规则不命中、已归档输入、base64 转换、超限和下载失败，
以及模型副本有句柄而持久化/公开内容不新增提示的边界。
需要工具消费 asset_id 时，同时验证该工具的查找和授权；句柄可见不等于可访问。
