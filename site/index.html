03 / Capabilities

支撑长期客户旅程的八项系统能力

Eight capabilities for the long arc of customer relationships

围绕记忆、状态、判断、目标与策略组织上下文，将理解人、执行行动、人工介入与结果反馈连接起来，让业务目标跨会话持续推进。

Organize context around memory, state, beliefs, goals, and policy. Connect human understanding, action, human oversight, and outcome feedback to advance goals across conversations.

跨会话记忆：延续客户关系Cross-session memory: sustain the relationship

保留历史交流、客户偏好与关键承诺，结合当前会话构建上下文。上周说“下个月再考虑”，再次沟通时能接续前情，减少客户重复说明。

Retain past exchanges, preferences, and commitments, then combine them with the current conversation. Pick up where the relationship left off, so customers do not need to explain everything again.

客户状态建模：理解变化中的人Human state modeling: understand change

业务应用可通过上下文扩展，组织客户意图、预算、信任、紧迫度与购买阶段；区分历史事实、当前状态与判断假设，为下一步行动提供依据。

Applications can use context extensions to organize intent, budget, trust, urgency, and buying stage. Separate historical facts, current state, and working beliefs to inform the next action.

长程任务推进：按策略持续跟进Long-horizon progression: follow up over time

任务状态跨天持久化；按业务目标拆解阶段，结合调度与唤醒策略，在资料补充、审批反馈或新方案出现时接续推进，形成观察、决策、行动与反馈闭环。

Persist task state across days. Break goals into stages and use scheduling and wakeup policies to continue after new documents, approval feedback, or a new offer, closing the loop from observation to action and feedback.

多步骤规划与工具执行Multi-step planning and tool execution

把查额度、算方案、约定回访等步骤连接起来，通过 Tool 对接业务系统执行操作；遇到异步审批或外部反馈时挂起等待，收到结果后恢复执行。

Connect steps such as checking eligibility, calculating offers, and arranging follow-up. Tools execute actions in business systems; suspend for asynchronous approvals or external feedback and resume when results arrive.

实时交互：响应新的意图Live interaction: respond to new intent

用户可在 Agent 执行中插话、打断或补充信息。新消息进入当前运行，Agent 结合已有上下文调整下一步，及时响应客户需求与约束的变化。

Users can interrupt or add information while the agent runs. New messages join the active run, allowing the agent to adjust its next step as needs and constraints change.

人机协同：关键时刻交给人Human-in-the-loop: involve people when it matters

通过工具挂起与恢复机制，支持应用在合规风险、重大权益或例外场景引入人工确认；携带必要上下文完成接力，处理后由 AI 继续推进。具体介入规则由业务应用定义。

Tool suspension and resumption let applications involve people for compliance risks, material rights, or exceptions. Carry the necessary context into the handoff and let AI continue afterwards. Applications define intervention policies.

快速接入：配置业务知识与行动Fast onboarding: configure knowledge and actions

通过 YAML 组合模型、工具、Skill 与知识库，将垂直领域知识和业务动作接入同一运行基础。配置平台提供在线编辑与 dry-run 校验，保存后重启生效。

Compose models, tools, skills, and knowledge bases in YAML to connect domain expertise and business actions. The configuration platform supports online editing and dry-run validation; save and restart to apply.

评测驱动进化：从反馈中改进Evaluation-driven evolution: learn from feedback

完整 Trace 支撑评测与失败归因，成功经验沉淀为可复用 Skill；候选版本通过回归评测后再发布。业务应用可围绕预约、到店、成交等目标定义评测口径。

Full traces support evaluation and failure diagnosis; successful patterns become reusable skills. Release candidates after regression evaluation. Applications can define evaluation criteria around appointments, visits, and conversion.

04 / Evolution

评测驱动的安全进化，而不是让 Agent 随意改自己

Evaluation-driven safe evolution, not an agent rewriting itself at will

HUMAN-CENTRIC LONG HORIZON AGENT 把自进化设计为数据运营驱动的迭代闭环：线上运行的完整 Trace 经分层评测分流—— 成功经验沉淀为 Skill 复用，失败案例归因后产出候选版本；候选与当前最佳对比、 通过 GoldenSet 回归评测后才允许发布。Test 是独立的手动动作，不参与优化选优。

HUMAN-CENTRIC LONG HORIZON AGENT evolves through a data-operations loop: full production traces are evaluated in layers and split — successes are distilled into reusable skills, while failures are diagnosed into challenger candidates. A candidate ships only after beating the current best and passing golden-set regression. Test is a separate manual action and never participates in selection.

方法设计服务三个目的：及时预警线上同类型大批量错误；沉淀优秀案例、复用成功经验； 让线上 case 自动修复并产出优化后的新版本。

The methodology serves three goals: early warning when the same kind of failure repeats at scale in production; distilling successful cases for reuse; and turning online failures into an improved new version automatically.

07 / Quickstart

从运行到进化，按模块开始 Start by module — from runtime to evolution

先完成一次公共准备，再按目标选择模块。启动后端只需要 Python 3.13+、uv 和 Docker；使用 Web 控制台时再准备 Node.js。实际调用模型前，请在 .env 中填写对应的模型配置。

Complete the shared setup once, then start only the modules you need. The backend requires Python 3.13+, uv, and Docker; the web console additionally requires Node.js. Add the relevant model configuration to .env before making real model calls.

公共准备Shared setup

安装依赖并创建本地配置Install dependencies and create local config

以下命令只需在仓库根目录执行一次。

Run these commands once from the repository root.

# shared setup · 公共准备
git clone https://github.com/YiXin-AILab/KinArc.git
cd KinArc
uv sync
cp .env.example .env

01 / Runtime

启动 Agent RuntimeStart the Agent Runtime

启动 Redis、API、Dispatcher 与调度器。对话、平台、评测和进化接口都由这个服务提供。

Start Redis, the API, Dispatcher, and scheduler. This service exposes chat, platform, evaluation, and evolution APIs.

docker compose -f deploy/runtime/docker-compose.yml up -d redis
uv run agentsystem

默认地址：Default endpoint: http://127.0.0.1:10060

02 / Console

打开 Web 控制台Open the web console

通过可视化界面测试对话，并管理 Agent、Skill、知识库、评测与进化任务。

Test conversations and manage agents, skills, knowledge bases, evaluation, and evolution from the UI.

cd web
npm ci
npm run dev

浏览器访问：Open in a browser: http://127.0.0.1:10061

03 / Evaluation

运行一次真实评测Run an evidence-based evaluation

从 eval_tasks/ 选择任务，运行真实 Agent Case，查看规则与 LLM Judge 报告。

Choose a task from eval_tasks/, run real agent cases, and inspect rule-based and LLM Judge reports.

EVAL_TASK_ID=your-task-id
curl -X POST \
  "http://127.0.0.1:10060/v1/evaluation/tasks/${EVAL_TASK_ID}/runs"

可视化入口：Visual entry point: /platform/evaluation

04 / Evolution

开启 Agent 自进化Start Agent evolution

基于 Train 与 Validation 证据自动诊断、修改、复评并保留更优候选版本。

Use Train and Validation evidence to diagnose, modify, re-evaluate, and retain better candidates.

EVOLUTION_TASK=evolution_tasks/your-task
uv run evolution run "$EVOLUTION_TASK" \
  --runtime-config config/runtime.yaml
uv run evolution status "$EVOLUTION_TASK"

可视化入口：Visual entry point: /platform/evolution
